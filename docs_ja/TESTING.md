## テストの実行

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

マルチ構成ジェネレータ（Visual Studio）では構成を指定する。

```powershell
cmake --build build --config Debug
ctest --test-dir build --build-config Debug --output-on-failure
```

CTest を介さずに 1 本だけ直接実行して出力を見ることもできる。

```bash
./build/tests/test_gradcheck             # 単一構成
.\build\tests\Debug\test_gradcheck.exe   # MSVC
```

テストがビルドされるのは `NNSCRATCH_BUILD_TESTS` が `ON` のときで、nnscratch が
トップレベルのプロジェクトなら既定で `ON`、`add_subdirectory` で取り込まれた場合は
`OFF` になる（[BUILD.md](BUILD.md#オプション)）。

テストには **Debug** を勧める。ツールチェーンによっては標準ライブラリのアサーション
が有効になり、そもそも最適化して得るものがないほど速い。CI は Release で走るので、
両構成が併せてカバーされる。

## ハーネス

`tests/check.hpp`、およそ 40 行。マクロ 2 つとカウンタ 1 つだけである。

```cpp
CHECK(expr);                      // 真偽のアサーション
CHECK_CLOSE(a, b, tol);           // |a - b| <= tol
return nntest::summary("suite");  // PASS/FAIL を表示し、終了コードを返す
```

失敗は `FAIL file:line expr` の形で表示され（`CHECK_CLOSE` なら実際の値と差も出る）、
カウンタを増やすが **中断はしない**。したがって 1 回の実行で最初の 1 件だけでなく
すべての失敗が分かる。壊れた `backward()` がサンプリングした数十点で失敗し、その
パターンを見たいときに効いてくる。

`summary()` は 0 か 1 を返し、CTest はプロセスの終了コードを読む。統合はこれで全部
である。フレームワークも登録マクロも、導入すべき依存関係もない。GoogleTest を
入れれば、これらのテストが使いもしない機能のために、プロジェクトの「依存関係ゼロ」
という原則を破ることになる。

## test_tensor

`Tensor` のプリミティブが forward で正しいことを、手計算した値と突き合わせる。

| 検証内容 | 方法 |
|---|---|
| `matmul` | $(2,3) \times (3,2)$ の積。4 つの要素（58, 64, 139, 154）を個別に検証 |
| `transpose` | 形状の入れ替えと 1 要素 |
| `sum_rows` | 形状と 2 列分の合計 |
| `add_row_vector` | 2 行にわたるブロードキャスト |
| `softmax` | 各行の和が 1、出力の順序がロジットの順序と一致 |
| `reshape` | データが保存され、形状だけが変わる |

許容誤差は $10^{-12}$ である。小さな整数の厳密な計算なので、これより緩めると本物の
バグを見逃す。

このテストが必要なのは、勾配チェックが誤った `forward()` を *捕まえられない* から
である。それ自体として整合しているが誤っている演算は、勾配チェックを平然と通過する。
手計算した期待値だけが唯一の防御になる。

## test_gradcheck

決定的なテストである。3 種類のネットワークの学習可能なパラメータすべてについて、
`backward()` が返す解析的勾配が $\partial L/\partial w$ の中心差分推定値と一致
しなければならない。理論的な背景 — なぜ中心差分か、なぜ $\epsilon = 10^{-5}$ か、
なぜその許容誤差か — は [MATH.md](MATH.md#勾配チェック) にある。ここでは実際の
手順を説明する。

### 対象のネットワーク

| ネットワーク | 検証対象 |
|---|---|
| `Dense → ReLU → Dense → Tanh → Dense`（8→6→5→4） | Dense, ReLU, Tanh |
| `Dense → Sigmoid → Dense`（6→5→3） | Sigmoid |
| `Conv2D(1→2, k=3) → ReLU → Flatten → Dense`（入力 (3,1,5,5)） | Conv2D, Flatten, ランク 4 の経路 |

ライブラリのすべてのレイヤー型が少なくとも 1 つに登場し、どのネットワークも
`SoftmaxCrossEntropy` で終わるので、融合された損失の勾配はすべての経路に含まれる。

ネットワークが小さいのは意図的である。1 点の検証につき forward が 2 回必要なので、
コミットごとに走らせられる速さを保つ必要がある。

### 手順

```cpp
// 1. 解析的勾配を一度だけ計算
Tensor logits = m.forward(X);
L.forward(logits, Y);
m.backward(L.backward());
auto pgs = m.params_and_grads();

// 2. パラメータテンソルごとに、およそ 16 要素をサンプリング
const std::size_t stride = std::max<std::size_t>(1, n / 16);
for (std::size_t i = 0; i < n; i += stride) {
    // 3. 要素 i における中心差分
    P->data()[i] = orig + eps;  const double lp = loss_of(m, L, X, Y);
    P->data()[i] = orig - eps;  const double lm = loss_of(m, L, X, Y);
    P->data()[i] = orig;                              // 厳密に復元する
    const double numeric = (lp - lm) / (2.0 * eps);
    CHECK_CLOSE(numeric, analytic[i], 1e-4 * (1.0 + std::fabs(analytic[i])));
}
```

重要な点が 3 つある。

- **解析的勾配はスナップショットを取る**（`pg.grad->data()` がコピーする）。
  probe の前に取るのがポイントで、`loss_of()` を呼ぶたびに新しい `forward()` が走って
  レイヤーのキャッシュを上書きするからである。スナップショットがなければ、摂動させた
  forward から得た勾配と比較することになる。
- **元の値は代入で復元する。** $\epsilon$ を引き戻すのではない。浮動小数点では
  `orig + eps - eps` は厳密に `orig` にならず、数百点の probe でずれが蓄積する。
- **全数ではなくサンプリングする。** `stride = max(1, n/16)` でテンソルあたり 16
  要素ほどを見る。誤った `backward()` が全体の $1/16$ だけ誤っているということは
  まずないので、検出力を失わずに数秒かかるテストを 1 秒未満にできる。

### 失敗したときの表示

```
FAIL  tests/test_gradcheck.cpp:47  numeric ~= analytic[i]   (|0.0231 - 0.0154| = 7.7e-03 > 1e-04)
2 failure(s) in gradcheck
```

この 2 つの数値が診断になる。[失敗の切り分け](#失敗の切り分け)を参照。

## test_optimizer

2 段階に分かれている。各オプティマイザを単体で、そしてスタック全体をエンドツーエンドで。

**単体。** SGD、Momentum、Adam のそれぞれが $f(w) = (w-3)^2$ を最小化する。勾配は
$2(w-3)$ として直接与えるので、レイヤーのコードは一切関与しない。500 ステップ後に
$w = 3$ から $10^{-2}$ 以内（SGD は $10^{-3}$ 以内）に到達しなければならない。符号の
誤り、学習率の適用ミス、Adam のバイアス補正の誤りを捕まえる。いずれも勾配チェック
では見えない。勾配チェックが検証するのは勾配であって、オプティマイザがそれを
どう使うかではないからである。

**エンドツーエンド。** 2→8→2 の MLP を、自明に分離可能な合成 2 クラス問題で 30
エポック学習させ、正解率 95% を超えなければならない。`train()` そのもののスモーク
テストであり — バッチ化、シャッフル、one-hot 化、指標計算 — 各部品は正しいのに
つなぎ方が誤っている場合に大きく失敗する。

## カバレッジの穴

テストされて *いない* ものを正直に列挙する。

| 未カバー | リスク |
|---|---|
| `load_digits` — パース、分割、正規化 | 中。デモが実行してはいるがアサーションはない。CSV パースのリグレッションはデモのクラッシュとして現れる |
| `write_pgm` / `write_pgm_grid` | 低。出力は目視で確認しており、そもそも I/O エラーを報告しない |
| エラー経路（形状不一致の例外） | 低。`matmul` が次元不一致で送出することを検証するテストはない |
| ストライド > 1 やパディング > 0 の `Conv2D` | **中〜高。** 勾配チェックはストライド 1、パディング 0 しか使っていない。col2im の `+=` 抜けがまさに見えなくなる設定である（[MATH.md](MATH.md#col2im-なぜ-scatter-add-なのか)） |
| 多チャネル入力の `Conv2D`（$C_{\mathrm{in}} > 1$） | 中。テストしている畳み込みは 1→2 チャネルである |
| ツールチェーン間の数値的再現性 | 設計上の割り切り。分布は移植性を持たない（[ARCHITECTURE.md](ARCHITECTURE.md#決定性)） |

最初に埋めるべきは `Conv2D` の穴である。ストライド 2、パディング 1、2 チャネルの
ケースを `grad_check` に足すのは数行で済み、ライブラリで最も誤りやすいコード経路を
カバーできる。

## テストを追加する

1. `tests/test_<name>.cpp` を書き、`main()` の最後を
   `return nntest::summary("<name>");` にする。
2. `tests/CMakeLists.txt` の `foreach` に `<name>` を足す。

   ```cmake
   foreach(test test_tensor test_gradcheck test_optimizer test_<name>)
   ```

これだけである。ループが実行ファイルを作り、`nnscratch` と警告インターフェースを
リンクし、CTest に登録する。

守るべき慣習:

- **シードはどこでも固定する。** 再現性が売りのライブラリで不安定なテストは、テストが
  ないより悪い。
- **本物のバグで失敗する程度に許容誤差を締める。** 厳密な算術には $10^{-12}$、
  有限差分には相対 $10^{-4}$。
- **実行時間は 1 秒未満に保つ。** 誰もスキップしたくならない速さを維持する。
- **新しいレイヤーは必ず `test_gradcheck.cpp` に追加する。**
  [CONTRIBUTING.md](../CONTRIBUTING.md) に明記された要件であり、
  [EXTENDING.md](EXTENDING.md#手順-4-勾配チェックで証明する) が手順を示している。

## 失敗の切り分け

`test_gradcheck` が失敗したとき、表示される 2 つの数値の比がたいていそのままバグを
指し示す。

| 症状 | 考えられる原因 |
|---|---|
| 解析値が数値微分のちょうど $N$ 倍 | バッチ平均の二重適用。損失がすでに $N$ で割っているのにバイアスの勾配も平均している、など（[MATH.md](MATH.md#記法と規約)） |
| 解析値が符号だけ逆 | 更新式または導関数の符号の取り違え |
| 解析値がゼロ、数値微分は非ゼロ | 勾配がパラメータに届いていない。`params_and_grads()` が誤ったポインタを返している、あるいは `backward()` が `d*_` メンバへの書き込みを忘れている |
| 数値微分がゼロ、解析値は非ゼロ | そのパラメータが実際には損失に影響していない。`forward()` の形状か添字のバグ |
| おおむね正しく、下位 2〜3 桁だけ違う | バグではない。有限差分のノイズである（[MATH.md](MATH.md#epsilon-の選び方)） |
| 1 要素だけ失敗し、シードを変えると場所が動く | probe が ReLU の折れ点をまたいでいる（[MATH.md](MATH.md#折れ点に関する注意)） |
| 特定の 1 レイヤーだけ全滅 | そのレイヤーの `backward()` が原因。上流が壊れていれば上流自身の probe も落ちるので、鎖の他の部分は正常である |

失敗しても中断しないので、1 回の実行で全体のパターン — どのレイヤーか、どの
パラメータか、誤差が一様（スケール係数）か散在（添字のバグ）か — が分かる。
