# 設計ノート

このドキュメントは、nnscratch における自明でないいくつかの設計判断を説明する。

## 単一の `Tensor` 型

このライブラリが必要とするのは、行列演算のためのランク 2 テンソル
`(rows, cols)` と、畳み込みのためのランク 4 テンソル `(N, C, H, W)` だけである。
汎用的な n 次元配列の抽象を導入するのではなく、`Tensor` はフラットで行優先の
`std::vector<double>` 1 本と小さな `shape` ベクトルを保持する。これは元となった
リファレンスの「numpy だけ」という精神を反映しつつ依存関係を持たずに済み、
`Conv2D` → `Flatten` → `Dense` をつなぐ `reshape`/`flatten` を概念的には
ゼロコピーにする。

## レイヤーインターフェース

すべてのレイヤーは以下を実装する。

```cpp
Tensor forward(const Tensor& x);          // backward が必要とするものをキャッシュ
Tensor backward(const Tensor& grad_out);  // 入力に対する勾配を返す
std::vector<ParamGrad> params_and_grads(); // 重みとその勾配を公開する
```

`ParamGrad` はポインタのペア `{Tensor* param, Tensor* grad}` である。
オプティマイザは `*param` をその場で書き換え、`param` の *アドレス* を
パラメータごとの状態（Momentum の速度、Adam のモーメント推定値）を管理する
安定したキーとして使う。これはリファレンスコードがオプティマイザの状態を
Python の `id(p)` でキーづけしていたことの C++ 版に相当する。

## softmax + cross-entropy の融合

`SoftmaxCrossEntropy` は意図的に softmax 活性化と cross-entropy 損失を融合する。
両者を同時に行うと、ロジットに対する損失の勾配が有名なほど単純な
`(prediction - target) / N` に collapse し、別個の（そして数値的に微妙な）
softmax ヤコビアンの掛け算を回避できる。内部で使う softmax は、数値安定性のため
指数化の前に各行の最大値を引く（数学的には何もしないのと等価）。

## im2col による畳み込み

`Conv2D` は古典的な im2col 変換を用いて、畳み込みを 1 回の行列積に落とし込む。
各出力位置の受容野を 1 行に展開することで、レイヤー全体が `col @ W` になる。
backward はこれを col2im で逆にたどり、勾配を入力へ scatter-add で書き戻す。
これにより畳み込みの forward と backward を、ライブラリの他の部分と同じ `matmul`
で表現でき、これはまさに PyTorch/TF のカーネルが内部で行っている落とし込みと同じ
である。

## 再現性

`Rng` は `std::mt19937_64` をラップする。比較デモは各モデルを構築する直前に
固定値でこれを再シードするので、競合する設定が同一のランダム重みから始まる。
そうしなければ、実験は調べたい変数ではなく初期化の運に交絡されてしまう。
ミニバッチの順序は *別の* 固定シードで駆動されるため、実行間で異なるのは
比較対象の軸だけになる。

## 正しさ: 勾配チェック

決定的なテストは `tests/test_gradcheck.cpp` である。学習可能なすべての
パラメータについて、`backward()` が返す解析的勾配を中心差分の推定値
`(L(w+eps) - L(w-eps)) / (2*eps)` と比較する。どのレイヤーであれ手で導いた
backward が誤っていれば（最も間違えやすい畳み込みも含めて）、このテストは失敗する。
これに通ることが、「from scratch」の数学が実際に正しいという証拠になる。
